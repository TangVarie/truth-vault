## 3. 整轮扫描账本（v1.25）

**要解决的事。** 原来判断「飞书里删了哪些帖」靠每篇笔记上的 `last_seen` 戳。三种情况它说不准：飞书那张表整张清空了（0 行，没有一篇能盖戳，等于没跑过）；一轮只写成了一部分；两趟同步并行时互相盖戳。

**现在怎么做。** 每趟同步在抓飞书之前先在账本里占一个顺序号。只有不带 `--limit`、每张表都抓全、库里已有的行都处理成了、note 都写进去了，才提交这一轮；0 行也照样提交。没提交的一轮下游看不见。`v_notes_vanished` 改成比「本项目最近一次已提交的一轮」：晚到的老一轮盖不掉新一轮，不看机器时钟。

- 提交和「这一轮见到了哪些篇」在一个数据库事务里，要么都成要么都不成。
- 这一轮见到了、但没处理成的新行（库里还没有对应 note 的）也记成「见到了」，免得别的一趟稍后把它建出来时被当成已删。库里已有 note 的行没处理成，照旧整轮不提交（D-058 没变）。
- **指标、账号没写成不挡提交**：这一轮见到了哪些篇，只要 note 写全了就成立。它们照旧计进 errors、这一轮照旧红，日志里多一行报数。
- 只报不删，没变：不删 note，不撤已经推出去的样本和经验卡。
- `Done:` 行里永远有 `scan_completed`（0 或 1）。

**迁移那一刻。** 把旧视图当时的分类原样带过来：每个盖过戳的项目建两条「历史」记录（最近一轮、更早的），从没盖过戳的项目不建。老篇的「最后见到」时间用的是它自己原来的戳，不是迁移那一刻的时间，所以写作台按 36 小时宽限判断的那个时间差不会被迁移抹成 0。历史上没记账的空扫描、失败扫描补不回来，等下一次成功的完整同步。

**库里还没跑 v1_25 时。** 同步在开头发现账本的函数不在（只认 PGRST202 / PGRST205 / 42883 / 42P01 这四个码），喊一次 warning，然后整条照 v1.25 之前的办法走：照常入库、照常盖戳、照旧按戳对账，`scan_completed=0`。下游三条路（新策展、通道 1、闸二取数）读的还是 `v_notes_vanished`，库里是哪一版就按哪一版。别的错（连不上、超时）不会被说成「去跑迁移」：照实报错、这一轮计一个 error，笔记和指标照常入库，只是不提交账本、不对账。

## 4. 特征恢复队列（v1.26）

细节在 [feature-annotation-recovery.md](feature-annotation-recovery.md)，这里只写要点。

- **问了模型、整篇一条有效答案都没有**：不落答案、不落完成标记，进队列，这一晚判红（这是这一晚新出的失败）。以前这种篇会留下一个完成标记，从此不再抽。
- **只有这一种情况记次数。** 第一次之后等约 20 小时，第二次之后等约 44 小时（夜跑每 24 小时一趟，所以下一晚、隔一晚的那一趟轮得到），第三次之后隔离，不再自动抽。接口报错、写库被拒、卫生断言没过、进程被杀，都不记次数，下一趟照常重试。
- **存量不让夜跑变红。** 队列里等着的和隔离的只报数：worker 的 `Done:` 行里有 `retry_deferred` / `retry_quarantined`，features-sync 收尾打一条 warning。计数脚本不把它们算进「还能抽几篇」，所以只剩存量时不会去叫 worker，也不花钱。
- **换过模型名不会反复重抽。** 一篇抽成功时，这一篇同一题库、同一 run_tag 下所有 `llm:` 开头标签的队列行一起清掉。生产换过模型名，迁移导入的历史行挂在旧名字下；不这样清，这些篇会每晚被重抽一次、每次都花钱、而且是绿的。
- **新的空答案不盖旧的有效答案**，在数据库的一条语句里判断，中间插不进别的写入。
- **手动回填**（backfill-features）用同一套判断：存量不算调用失败；一批里有篇零有效就不重发这一批，一篇都没抽成就停。
- **库里还没跑 v1_26 时**：worker 喊一次 warning，照 v1.26 之前的办法抽（不建队列、直接写答案）；features-sync 收尾在 run 页面上打一条「迁移还没跑 (notes_v1_26)」。别的错照实报。
- **占位那一下没成**（库抖了一下、超时）：只跳过那一篇，不调模型、不记次数，这一批剩下的照常抽；整批都这样才判红。

## 6. 回滚

- 只回滚代码、不动库：可以。老代码不认识账本和队列，会照老办法跑；`v_notes_vanished` 这时还是 v1.25 那一版，而老代码不再提交新的一轮，视图会停在最后一次提交的样子。要长期回到老代码，得再跑一次 v1_21 把视图换回去。
- 不要为了「清告警」去删账本或队列里的行。
