# docs/archive/ —— 只作历史，不要照着做决定

这里面是**某个时刻的交接记录和审计快照**。它们由构造决定就是历史：一份写着
「2026-06-04 交接」的文档，描述的就是那一天的状态，不是今天的状态。

**不要照着它们干活。** 里面提到的表、脚本、接线方式有些已经不在了。

保留它们的理由只有一个：**回答「当时为什么这么做」**。真要追某个决定的来龙去脉，
先查 `DECISIONS.md`（那是活的、append-only 的），查不到再来这里。

## 当前有效的入口

| 想知道什么 | 看哪儿 |
|---|---|
| 整个系统怎么串起来、写一篇稿碰哪些表 | `docs/00-START-HERE.md` 的数据流向图 |
| 每个决定为什么这么做 | `DECISIONS.md` |
| 每盏灯谁看、多久看、红了谁负责 | `docs/29-lights-registry.md` |
| 夜跑怎么跑、出问题怎么查 | `scripts/README.md`、`docs/12-daily-sync-troubleshooting.md` |

## 归档的判据

**只归档「由构造决定就是历史」的文档** —— 带日期的交接记录、某次审计的快照。

⚠️ **不按「多久没改过」归档。** 2026-09-21 试过一次，当场发现是错的：
`docs/02-schema-v1.md`、`03-mapping-protocol.md`、`09-system-integration.md`
这些确实半年没动，但 `scripts/_common.py` 正引用着它们 —— 它们不是死了，是
**稳定且仍然正确**。规格本来就不该天天变。按时间归档会把活代码的引用改断，
并且归档掉仍然正确的规格，比不归档更糟。

一份文档过期与否，判据是**它说的东西还在不在**，不是它什么时候改的。
