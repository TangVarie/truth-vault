# prompts/flywheel_librarian.md · 飞轮"馆员"选取 prompt (v1)

**用途**: pull 模型的【借阅端】。写稿时,LLM 馆员拿一个写作 **brief** + 一批【已验证爆款/
值得参考】的"经验卡"(由策展 pass 产出,见 `prompts/flywheel_curator.md`),**推理挑选
3-5 张最有借鉴价值的**,并说清每张【为什么相关】+【借它哪个部位】。由
`librarian/core.py` 调用。运行时为 **prompt caching 分块结构**(`core.py`):`ROLE_TASK_INSTR`
+ 候选卡 → 第 1 个 `cache_control: ephemeral` system 块(**同项目内**、同 library_version 内稳定 —— D-088 起候选按项目预筛,不再跨项目共享;审计 C-05 改此句);
项目 prompt 包 → 第 2 个缓存块(按项目);本次 delta → user message(每次变、不缓存)。
改本文件时同步 `core.py` 的 `ROLE_TASK_INSTR`。

背景: D-038 / docs/14。**馆员 ≠ 策展员**:
- 策展(`flywheel_curator.md`): 入库时把**单条**生贴提炼成一张经验卡。
- 馆员(本文件): 写稿时从**多张**卡里**按 brief 推理选取**。这是 §2 说的"判断,不是
  embedding 相似度检索"——馆员要权衡这次写作到底需要借哪几条、借哪个部位,可跨主题迁移。

## 输入

- **brief**: 品牌 / 项目定位(system_prompt 包) / 本次策略·核心卖点·人群·选题(delta)。
- **候选经验卡**(按 `rank_score` 排序, **≤24 张**): 每张含 `source_note_id` / tier / 品牌·品类 /
  hook_type / structure / why_it_worked / transferable_tactic / 原文摘要。未策展的卡
  (经验字段为 NULL)用 essence + 摘要兜底。
  **怎么来的(D-088, `core.shortlist`)**: 整架取回(306 张), 按 brief 的【项目级】字段打贴题分
  (同品牌 +3 · 同品类 +2 · 人群词 +1)挑 24 张, 另外 rank 全局前 8 张无条件保留(跨主题迁移要有料)。
  只看项目级字段、不看本次 delta —— 同项目内候选块稳定, prompt cache 才命中。零维护、不是规则表。

## 输出 (严格 JSON, 无 markdown 包装)

```json
{"selected": [
  {"source_note_id": "<必须是候选里出现过的 id>",
   "why_relevant": "<为什么对这次写作有用, 1 句>",
   "borrow_what": "<借它哪个部位: 钩子 / 结构 / 评论区设计 / 某个手法, 1 句>"}
]}
```

## 约束

1. 严格 JSON;`selected` 3-5 条(候选不足就少选;**一条都不合适就返回空数组**——宁缺毋滥)。
2. `source_note_id` **必须**来自候选清单(不许编)。服务端会再校验、丢弃编造的 id。
3. **推理选取**, 不是按相似度硬凑: 优先同品牌/同品类/同人群, 但允许跨主题借走可迁移的
   钩子/结构/手法(§2 的"跨主题迁移")。
4. `why_relevant` / `borrow_what` **各 ≤30 字**, 给写手**可操作**的指引, 别复述卡内容、别加评语。
   (D-088: 冷路径耗时大头是模型写出来的这几百 token 走中转站, 不是读卡; `max_tokens` 封顶 1000 兜底。)

## 已验证规律（P4，D-116，2026-10-16 起）

- **来源**：`prompts/desk_delivery_v1.json`，闸二结论之上的人工批准层，不在冻结题库里。批准层的 `gate2_run` 和库里最新一轮闸二对不上时，整份不下发（fail-closed）。标签对上了还要对内容：闸二允许拿已有标签重跑（upsert 覆盖），所以下发前查一次库里这一轮的行，每个下发的取值都还是 validated、方向和题库版本都没变才下发；查不了也不下发。核对结果在进程里留 10 分钟；查不了只记 30 秒，库一恢复就重查。
- **馆员怎么用**（`librarian/patterns.py`）：
  - 第 1 个缓存块里，在 `ROLE_TASK_INSTR` 之后、候选卡之前，加一段「已验证规律」：每条一句可照做的话加证据。这段全局稳定，放在卡前面。
  - 冷路径给进了 shortlist 的卡算命中：查 `note_feature_answers` 里这张卡源笔记的答案（闸二同一份快照：primary × 题库摘要 × 两个抽取器）。卡面多一行「命中已验证规律: …」。「品牌别硬插」只算露了品牌的卡（`未出现` 的不算：它被 owner 压着，不能借命中从后门推）。批准层里 `examples: false` 的规律只下发指令、不给卡标命中（D-134 起「品牌别硬插」就是这样：它的「后20%」八成是连写话题标签的残渣，正文其实没提品牌）。查库失败就不标命中，不阻塞选卡，这次的结果也不写缓存（库恢复后同样的请求要能重新标上）。shortlist 里有 48 小时内新策展、还没抽特征的卡时同理不写缓存：策展在 daily-sync（02:17 UTC），抽特征在 features-sync（12:47 UTC），答案进库不改版本串。老卡没答案就是永远没有，照写缓存。拿 `run_tag=primary` 重抽答案（backfill-features 的 reannotate）之后，工作流跑 `prune_librarian_cache.py --delivery-only`，清掉所有带规律下发的缓存行：重抽改了答案却不改版本串。
  - 选中的卡带 `validated_hits`（规律标签名列表）；HTTP 响应多一个 `patterns`（id / label / instruction / evidence）。老消费方不认这两个字段，不受影响。
  - 模型被要求：同样合适时优先借命中规律的卡，`borrow_what` 写明借的是哪一条；不要为了凑规律去借不相关的卡。
- **分臂**（docs/28 §7.4）：只有显式带了 `explore` 的消费方才参与。
  - `explore: false` 是规律臂。
  - `explore: true` 是探索臂（写作台 15% 的批次）：规律段、命中、`patterns` 全都不给，缓存键也和规律臂分开。对照组要的就是「没被规律影响过」的选卡。
  - 不带这个键的老消费方（通道 1、旧版写作台）不下发规律，缓存键也和以前一样。所以 TV 先上线、写作台还没开始分臂的那段时间，不会出现「全是规律臂、对照组为空」。
- **缓存版本**：`library_version` 末尾加 `:dl<批准层摘要>`，探索臂再加 `:explore`。批准层改一版，旧缓存就失效。两样都没有时，版本串和以前完全一样。
- 守卫：`scripts/check_desk_delivery.py`，7 节。

## 外部参考书架（D-117 ②，2026-10-16 起）

- **来源**：`truth_vault.external_notes`（Jev 每周抓的别家帖），配置 `prompts/external_shelf_v1.json`，代码 `librarian/external.py`。不进 `truth_vault.notes`，不当爆文。
- **谁有**：只给显式带了 `explore` 的消费方（写作台），规律臂、探索臂都给（两臂只差规律，对照才干净）。不带这个键的老消费方不给，缓存键也不变。
- **同品类**：brief 的品牌 / 项目名里出现配置里某品类登记的品牌名，才给那个品类的外部卡。只看品牌和项目名，不看项目定位（定位里顺嘴提到「戒烟」不算）。
- **上架条件**：评论 ≥50（和判爆同一把尺子）、Jev 分诊判了没带产品、不像广告、标题正文里没点到**我们登记的品牌**（点了的多半是我们自己铺的帖）。别家品牌名（`mask_terms`，周更里见到新的就补进去）不挡，上架时换成「某品牌」（D-120）。每个品类按评论数取前 6 张给模型看。
- **卡面**：id 是 `ext:<外部 note_id>`，没有品牌；卡头写「外部参考｜品类｜别家同品类帖, 只借结构不抄内容, 别提它的品牌」，带评论数和 200 字摘要。有外部卡时，候选卡前面多一句用法：最多挑 2 张、只借结构、同样合适时优先帆谷自己的卡。
- **截断**：模型多挑了外部卡，按它给的顺序留前 2 张，其余丢掉（不算契约失败），丢掉的不占 5 张的名额。选中的卡都带 `external`（true / false）；部署前写的缓存行没有这个键，命中时补成 false。
- **书架按品类在进程里留 10 分钟**：外部表一周才进一次货，不必每个请求（包括命中缓存的）都去拉正文。查库失败不留，下个请求重查。
- **缓存版本**：有外部卡时 `library_version` 末尾加 `:ext<外部卡 id 摘要>`；Jev 周更换了一批，旧缓存就失效。没有外部卡时不变。
- fail-open：配置读不了、外部表查不了，这次就没有外部卡，内部卡照常选。
- 守卫：`scripts/check_external_shelf.py`，7 节。每周方向复核 `scripts/check_external_direction.py`（daily-sync，每周一）顺带报每个品类达标几张。
